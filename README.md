# 等值线提取（从 0 实现）

起始环境只有这份说明、`samples/**` 和 `.gitignore`，没有实现代码：等值线引擎（库 + 命令行入口）和一页原生 HTML/内联 SVG 的等值线图都从零写，用 Python 3.13 标准库，不引第三方、不加构建。给一份网格和一组等值面，输出每条线的点序列；同一份网格跑两遍，线的集合、顺序与坐标必须一字不差；百万格的网格要几秒出结果。

## 一、范围

做：读网格文件（行列、间距、取值、等值面表）；按一组等值面提取等值线；按口径把线段连成整条线并排序；写文本结果；生成一页内联 SVG 页面（网格打底 + 等值线 + 端点 + 计数）；命令行入口；`unittest` 测试。

不做：不做三角网格、不规则网格与三维体绘制；一次只处理网格文件里那一组等值面；不做重采样、平滑与抽稀，线只由格边上的插值交叉点直连；不做缺失值、掩膜与坐标变换；不做并发与缓存；不引第三方依赖、不加构建；页面只画不重算，逐行验收看文本结果。

## 二、口径与公式

- 网格是正交均匀网格：格点 `(i, j)`（`0 ≤ i < ncols`、`0 ≤ j < nrows`）的坐标是 `x = x0 + i*dx`、`y = y0 + j*dy`；四个相邻格点围成一个格胞，共 `(ncols-1)*(nrows-1)` 个格胞。
- 高低侧：格点值 `v ≥ level` 记「高」，否则记「低」。**等于 level 的格点算高**，压格点与同值区域的连法全靠这一条定。
- 插值：格边两端一高一低时，该边恰有一个交叉点。设边从 `A`（值 `a`）到 `B`（值 `b`），`t = (level - a) / (b - a)`，坐标 `P = A + t*(B - A)`；`a == level` 取 `t = 0`、`b == level` 取 `t = 1`，直接取格点坐标、不做浮点插值。线段端点因此只落在格边上，格胞内的线段就是两条交叉点之间的直线段。
- 连线：四角全高或全低的格胞不出线；只有一个孤角（一角高、或三角高）就用一条线把这个孤角切掉；相邻两角高就把这两角所在的一侧切掉；每条线段的走向让「高角在左、低角在右」，整条线于是绕高区逆时针。
- 鞍点：对角两角高时，先算格心值 `c = (v_BL + v_BR + v_TR + v_TL) / 4`（就是双线性插值在格心的值）：`c ≥ level` 两个高角连通，两根线分别圈住两个低角；`c < level` 两个高角各自孤立，两根线分别圈住两个高角。
- 边界开口：交叉点落在网格外边界（外框四条边）上时，它就是线的端点，线到此为止；不沿边界绕行，边界外不存在。
- 退化：两端点坐标相同的线段直接丢弃（例如孤角的值正好等于 level、四邻都低）；丢弃不影响其余点之间的连接。
- 精度：坐标与 level 一律 6 位小数（四舍五入），`-0.000000` 写成 `0.000000`；插值用双精度浮点，比对容差 1e-6。

## 三、数据结构与流程

- `Grid`：`ncols`、`nrows`、`x0`、`y0`、`dx`、`dy`、`values`（按行）、`levels`。
- `Contour`：`level`、`points`（点序列）、`closed`。
- 一次提取：读网格 → 逐等值面扫格胞（四角值算完先取最小/最大，落在区间外的等值面不做重活）→ 每个格胞产出 0 或 2 条有向线段 → 端点坐标相同就接在一起（按坐标对齐，不依赖遍历顺序）→ 每个点至多一进一出 → 排序 → 写文本与页面。库的 API 自定。

## 四、输入输出与文件格式

本节文本文件一律 UTF-8、LF、末行有换行。

### 4.1 网格文件 `samples/grids/<案例>.txt`

固定 7 行头加 `nrows` 行数值，不空行、不注释；数值行按 `j` 从小到大排，行内按 `i` 从小到大：

```
ncols 7
nrows 7
x0 0.0
y0 0.0
dx 0.5
dy 0.5
levels 1.25 2.25
0.0 0.0 0.25 0.5 0.25 0.0 0.0
（其后还有 6 行）
```

`levels` 是 1..8 个严格递增的等值面。读入容错：行尾空白、CRLF、数值写成整数都接受。

### 4.2 结果文件 `lines.txt`

一条线一块，形如：

```
LINE <level> <点数> <CLOSED|OPEN>
<x> <y>
（其后还有「点数」行）
```

字段之间一个空格。`CLOSED` 的点序列不重复首点，首尾相连由标记表示。全文件顺序：先按 `level` 升序，同一 level 内按点序列字典序升序（先比首点，首点相同再比第二个点）。闭合线的起点取序列里字典序最小的点；开放线的起点是唯一那个「没有入线段」的端点（另一端没有出线段），样例里这两端都落在网格外边界上。

### 4.3 命令行与页面

```
python -m isodraw extract --grid <网格文件> --out <输出目录>
```

写出 `<输出目录>/lines.txt` 与 `<输出目录>/index.html`，往 stdout 打一行 `STAT|lines=<条数>|max_segments=<最长线的段数>`；参数或网格不合法时非 0 退出，不留半成品。页面放 `web/index.html`：原生 HTML + 内联 SVG，无外部资源，`file://` 直接打开；网格按值铺底色，等值线叠在上面，端点用小点标出，底部标注这次提取了多少条线、最长的那条有多少段。页面里的线段与端点必须逐点取自引擎结果（命令行生成的 `index.html` 与 `web/` 下的入口是同一份内容即可），页面只画不重算。

## 五、性能与验收口径

Windows + Python 3.13、单进程单线程、只用标准库。`scale` 样例（1000×1000 格点、998001 个格胞、3 个等值面）单次运行（读网格 + 提取 + 写文本与页面）≤ 10 秒，峰值内存 ≤ 512 MiB。

1. 逐样例跑命令行，`lines.txt` 与 `samples/expected/<案例>.txt` 逐行一致：浮点按 1e-6 容差比，其余字符逐字节相同、行序相同。
2. 端点落在格边上：每条线的每个点，或者 `y` 等于某条格线且 `x` 落在相邻两条格线之间，或者 `x` 等于某条格线且 `y` 落在相邻两条格线之间。
3. 确定性：同一份网格连跑两遍（含改 `PYTHONHASHSEED`），`lines.txt` 与 `STAT` 行逐字节相同；不读时钟、不用随机数、输出顺序不依赖容器遍历顺序。
4. 页面只做人工查看，不参与逐行比对；底部计数必须与 `lines.txt` 对得上。
5. 测试写在 `unittest` 里，只读 `samples/**`，写只写 `var/`。

## 六、样例说明

`samples/grids/<案例>.txt` 与 `samples/expected/<案例>.txt` 一一对应，覆盖平滑山丘、双峰鞍点、等值线正好压格点、大片同值区域、边界上出现开口，外加一份百万格规模样例。

- `hill`：7×7、`dx=dy=0.5`，中心一个尖；`1.25` 出 1 条 12 点闭合线，`2.25` 出 1 条 4 点闭合线。
- `saddle`：6×6，两块 2×2 高区对角相接；`0.5` 时格心 1.0 判连通，出 1 条 16 点闭合线；`1.5` 时判分离，出 2 条 8 点闭合线。
- `onpoint`：5×5，`x0=-1`、`y0=10`、`dx=2`、`dy=0.5`；`2.0` 正好压在整圈格点上，出 1 条 12 点闭合线，顶点全是格点坐标，四个外圈角按格胞对角切掉。
- `plateau`：6×5，一块 4×3 的格点值正好等于 `1.0`；出 1 条 10 点闭合线，线段落在格边上；四个角胞各有 1 条零长度线段，按规则丢弃。
- `open`：4×4 的斜平面；`3.5` 与 `6.5` 各出 1 条 5 点开放线，端点分别落在上/下边界与上/右边界上。
- `scale`：1000×1000；`0.5`、`1.5`、`2.5` 各出 1 条 1000 点开放线，用来压时限。

`samples/notes.md` 是现场记录，只作背景，不作为口径。
